Core Architecture

The Redux Mental Model: The Bank Ledger Analogy

In simple apps, developers mutate variables directly (state.balance = 5000). In large enterprise apps, direct mutation creates hidden side effects, race conditions, and un-debuggable state.

🏛️ 1. Single Source of Truth

The entire application state is stored in a single immutable object tree inside the Store.

🧾 2. State is Read-Only

To change state, you cannot assign properties. You must issue an Action voucher capturing intent.

⚙️ 3. Pure Transitions

Reducers are strictly pure functions: (state, action) => newState with zero side-effects.

💡
Why Immutability Matters: Because reducers return a new state reference (via object spread { ...state }), components and selectors can perform instant $O(1)$ reference comparisons (prevState === nextState) rather than deeply checking thousands of nested properties!
