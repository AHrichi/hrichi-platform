3. Concurrency Cheatsheet

Choosing the Right Operator

exhaustMap Ignores new source emissions until current inner observable completes. Perfect for submit buttons, logins, and checkout actions to prevent double submissions.
switchMap Unsubscribes from previous inner request when a new action arrives. Perfect for search/autocomplete filters where only the latest query matters.
concatMap Buffers incoming actions and processes them sequentially in strict order. Perfect for queued file uploads or chronological transactions.
mergeMap Executes all inner requests concurrently. Perfect for independent background syncs where ordering and duplicate prevention do not matter.

Production Reliability

The "Dead Stream" Trap & Why tapResponse is Vital

The #1 most common junior/intermediate bug in NgRx is putting catchError() directly on the outer actions$.pipe(...) stream instead of the inner HTTP observable.

❌ Fatal: Outer catchError Kills Effect 
actions$.pipe(
  ofType(AuthActions.login),
  switchMap(() => api.login()),
  catchError(err => of(AuthActions.failure({ err })))
  // 💀 Outer actions stream COMPLETES!
  // Future login clicks will NEVER fire!
)
✅ Production Safe: tapResponse 
actions$.pipe(
  ofType(AuthActions.login),
  switchMap(() => api.login().pipe(
    tapResponse({
      next: (user) => AuthActions.success({ user }),
      error: (err) => AuthActions.failure({ err }),
    })
  ))
  // 🛡️ Outer stream remains ALIVE forever!
)
